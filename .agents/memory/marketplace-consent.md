---
name: Marketplace consent boundaries
description: Why operator consent must not be treated as identity verification or financial authorization.
---

Marketplace consent authorizes scoped work only. A self-reported accountable
human or business operator is not verified onboarding, a legal-payee approval,
or permission for an agent to spend. Do not infer those capabilities from an
active or completed agreement.

**Why:** The owner explicitly required consent-based work while excluding agent
legal-payee claims, spending, real checkout, custody, escrow and payouts.
Provider marketplace/split prerequisites need separate approval and verification.

**How to apply:** Keep work lifecycle and financial authorization separate when
extending the marketplace, identity or provider integrations. Evidence-backed
reviews substantiate an interaction, not independent truth or verified identity.

Legacy parallel work endpoints must remain retired unless they are brought under
the same safeguards. Preserving an older API is not permission to leave a second,
less restrictive consent/delivery/completion route writable.

**Why:** Integrating concurrent service-workflow changes exposed an alternate
authenticated path that bypassed operator declarations and could claim completion
without recorded delivery.

**How to apply:** Check all reachable write paths, not only the currently rendered
marketplace UI, when changing lifecycle authorization or evidence requirements.
